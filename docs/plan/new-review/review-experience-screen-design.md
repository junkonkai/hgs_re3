# レビュー体験入力・画面設計（試作）

作成日：2026-09-12

状態：合意した入力案を操作して確かめる試作仕様。本番仕様・正式名称の確定ではない。

## 目的と資料の関係

「ホラーゲームとしての面白さ」を、作品にある要素と本人の体験を結び付けて伝える。ユーザーとゲームのつながりは密、ユーザー同士のつながりは疎という方針を前提にする。

- [サイト全体の方針](../site-matching-direction.md)：最新の合意は第9節。
- [以前のアンケート具体案](review-preference-prototype.md)：好みの収集・本人設定と推測の区別を引き継ぐ。今回の試作は作品単位のレビューであり、普段の好みアンケートの置き換えではない。
- [試作HTML](review-experience-prototype.html)：ローカルブラウザで開いて操作する。既存の `questionnaire.html` は保持する。

## 合意した内容

- ゲーム詳細に、体験ごとに整理したレビューへの入口を置く。AI要約の具体的方法は未決定。
- 運営タグは作品の特徴、レビューの選択は本人の体験。共通要素を使っても両者を混同しない。
- 未登録要素をユーザーから提案できる方向。運営タグへの昇格・承認方法は未決定。
- 下記の五項目を土台とする。大項目だけでも回答でき、詳細選択と自由文は任意。
- 楽しめた／気になったは両立可能。怖さの種類・楽しめたか・怖さの強度は別。
- サイト本体と分けた単独HTMLをSolが実装し、親エージェントが資料整理・完成後のレビューを行う。

## 画面構成

1. 作品名、試作の説明、サンプル読込・空に戻す操作。
2. レビュー入力（以下の五項目）。
3. 短いレビュー表示と全文プレビュー。画面幅に応じて並列または縦配置。
4. チャットに貼るためのテキスト出力とコピー。コピーできない環境では手動選択できる。

実投稿、サーバー保存、外部通信は行わない。タブを閉じる・再読み込みする前に必要な回答をコピーする。AI生成・総合点・相性点・怖さ強度・本番ゲーム詳細の集約表示は今回の範囲外。

### 1. このゲームで楽しめたところは？

大項目は複数選択可・任意。追加の詳細は開いた人だけが選べる。

| 大項目 | 詳細候補 |
|---|---|
| 物語・登場人物 | 続きが気になる展開／謎や真相／登場人物／人物同士の関係 |
| 探索・発見 | 寄り道／アイテム収集／手掛かり探し／隠された場所の発見 |
| 戦闘・対抗 | 狙って攻撃する／タイミングを見極める／敵への対処を考える |
| 逃走・潜伏 | 追跡から逃げ切る／隠れてやり過ごす／敵の気配を読む |
| 謎解き・推理 | 仕掛けを解く／情報を組み合わせる／異変を見つける |
| 資源管理・サバイバル | 限られた物資のやりくり／危険を冒すか判断する |
| 世界観・雰囲気 | 舞台や風景／音の演出／不穏さ／怪異や敵の表現 |

本番では作品タグを関連項目の提示に使う構想だが、今回の候補は汎用の仮リスト。作品の検証済みタグとしては扱わない。

### 2. どんな怖さが印象に残りましたか？

複数選択可・任意。

- いつ何が起こるか分からない不安
- 敵や怪異が近くにいる気配
- 追われる恐怖
- 抵抗できない心細さ
- 突然の出現や大きな音による驚き
- 不気味な光景や異変
- 真相を知るほど深まる恐怖
- 残酷な描写や身体の変化

各選択に「楽しめた」「苦手だった」を独立した任意回答として付ける。両方選択可能。無回答は「中立」「楽しめなかった」へ変換しない。

### 3. 特に惹かれたところは？

1で選んだ要素、および2で「楽しめた」と回答した怖さから任意で複数選ぶ。短い表示でも本人が重視したものが分かるようにする。

### 4. 気になったところはありますか？

任意で開く。1の大項目と同じ要素に、操作のしづらさ・不具合などを加える。1との重複を許す。旧作比較などの事情は自由文で補う。

未登録の要素を提案する任意欄も試す。これはアシスタントによる配置の仮仕様であり、五項目の選択回答や運営タグへ自動変換しない。

### 5. 感想を書く

任意の自由文を一欄にまとめる。要素別の理由入力を要求しない。「怖いが続きを知りたい」という関係や、「旧作の方が好みだが今作も面白かったかもしれない」という留保を原文のまま残す。

## 試作で置く仮仕様

- 初期状態は空。サンプルは明示操作で読み込む。サンプルの選択はアシスタントの仮置きと表示する。
- 対象作品は「零～紅い蝶～REMAKE」に固定。短いレビューは原文を4行まで表示し、全文は別の開閉領域で確認する。
- 大項目の解除では配下の詳細回答を消す。怖さの解除では配下の楽しめた／苦手だったを消す。
- 「特に惹かれた」の元回答を解除した場合、対応する選択を消して孤立データを残さない。
- 折りたたむだけでは回答を消さない。
- 文章はHTMLとして解釈しない。選択のみから具体的な理由文を生成しない。
- 入力・全文・出力で、選択の重複、未回答、本人の文章を保持する。
- 本番の保存方式、必須条件、入力上限、ネタバレ制御、既存レビューの移行は未決定。
- 単独HTMLなのでCSS/JSを内包する。公開Bladeの構造やアプリのライフサイクルを変更するものではない。試作固有の配置を共通デザイン決定にはしない。

## 試回答：零～紅い蝶～REMAKE

以下はユーザー本人の体験であり、作品仕様の外部検証は行っていない。

> 敵がランダム発生だったりするので、いつ出てくるか分からない怖さと、シナリオが良いので早く進めて続きを見たいという気持ちがせめぎあう。今作では探索要素（アイテム収集や、一定の地点で撮影するなど）もしっかり用意されていて、本編とは違う道でアイテム探しをする楽しさもあった。敵との戦闘はリメイク前の方がよかったものの、ややTPSシューター風にアレンジされた感じがあるので、TPSシューターゲームが好きな身としてはこれはこれで面白かったかもしれない。まぁでもやっぱりこのゲームはシナリオがいい。

仮の選択：物語（続きが気になる展開）、探索（寄り道・アイテム収集）、戦闘（狙って攻撃する）。印象に残った怖さは「いつ何が起こるか分からない不安」で、楽しめた／苦手だったは未回答。特に惹かれたのは物語。気になったのは戦闘。これらは本人が実際に選んだ回答として扱わない。

## レビューで確認すること

- 空・選択のみ・自由文のみで利用できるか。
- 大項目だけの回答、詳細の任意性、両立する回答を保てるか。
- 元回答解除後に詳細や強調が残らないか。折りたたみで回答を失わないか。
- サンプルの原文と留保、未知の反応を保持しているか。
- 短い表示から全文へ進み、全回答を確認できるか。
- デスクトップ／モバイルのChromiumでスクリーンショットを目視し、横スクロール、キーボード操作、低減モーション、JS無効時の案内を確認する。
- チャット出力とコピー失敗時の代替が使えるか。外部通信や実投稿がないか。

入力負担、選択肢の粒度、選択肢では表せない内容は、ユーザーが触った後で再検討する。

## 実装後レビュー記録（2026-09-12）

実装担当：GPT-5.6 Solサブエージェント。レビュー担当：親エージェント。

初版では「特に惹かれた」の候補DOMが回答のたびに再生成され、Space操作後にキーボードフォーカスを失った。Chromiumで再現し、候補の組み合わせが変わった場合だけ再生成するよう修正した。また短い表示が全文のままだったため4行表示へ変更し、入力手段のない「作品名未入力」は対象作品の固定表示に変更した。

修正後にChromiumで以下を確認した。

- 初期空、サンプル読込、解除、自由文のみの入力。
- サンプル原文と本資料の引用の完全一致。怖さの反応は未回答を維持。
- 楽しめた／苦手だったの両立と出力、親回答解除に伴う詳細・反応・強調の解除。
- 詳細を閉じても回答を保持し、Spaceで選んでもフォーカスを保持。
- HTMLに見える自由文を文字として表示し、実行しない。
- コピー拒否時の全選択による代替、全文プレビューとチャット出力。
- 1440px・390pxのスクリーンショットを目視。320pxでも横スクロールなし。低減モーション下で操作可能。JS無効時は利用案内を表示。
- ブラウザのページエラーなし。HTML内JS構文確認、`git diff --check` 成功。

対象は単独HTMLと設計資料だけで、Laravel・Viteの実行経路には変更がないため、アプリ全体のビルド・PHPテスト・DB操作は行っていない。確認用スクリプトと画像は `/tmp/hgn-review-*` に作成した一時成果物。

次の相談では「サンプル回答を読み込む」から選択を変えるか、「空の状態に戻す」から回答し、チャット用テキストと一緒に、選びにくかった項目・余分だった項目・表せなかった体験を共有する。
