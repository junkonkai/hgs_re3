## 位置付け

[設計メモ](review-preference-design.md) を具体的な利用例にした検討用の試案。実装や採用が確定した仕様ではない。質問・表示文言も仮置き。以下の人物、作品X・Y・Z、投稿は架空で、実レビューの引用ではない。

目的は、本人の好みと作品での体験を結び付け、読む人が自分に合うかを判断できること。総合点・相性点はこの試案では使わない。既存点数の廃止・移行は別途決定する。

## 1. 今回具体化する考え方

- ゲームの楽しみ方と、ホラー表現の好き嫌いを聞く。
- 怖さは遊びを強める要素にも、楽しみの中心にも、妨げにもなる。
- 怖さの強さ、怖さを好むか、その作品が全体として合ったかを分ける。
- 「要素 → その作品での作用 → 本人の反応」をレビューに残す。
- 一作品への反応から、恒常的な好みを断定しない。

## 2. 初回アンケート

登録完了後やプロフィールから任意で開始する。途中で終了・後から修正でき、未回答でもレビューを投稿できる。すべての項目への回答を要求しない。

### 問1：ゲームで、どんなことを楽しみたいですか？

複数選択、個数制限なし。ここで選ばなかった項目は「嫌い」ではなく未申告。

- 戦闘や操作が上達すること
- 敵を倒す爽快感
- 場所を探索して発見すること
- 謎や仕掛けを解くこと
- 登場人物や物語を追うこと
- 手掛かりから背景を考察すること
- 道具や物資の使い方を考えること
- 自分で方法を工夫すること
- まだ分からない／その他（任意記述）

これは探索用の候補で、全ジャンルを網羅した分類ではない。協力プレイなどの項目追加は対象作品を広げた検証で判断する。

### 問2：選んだ楽しみ方について、近いものはありますか？

問1で選んだ項目から詳細を表示する。最初は一項目だけでも回答でき、残りは後から追加可能。各文を独立して「好き／どちらでもない／避けたい／分からない」で回答する。「どちらでもない」と未回答を区別する。「どちらでもない」は特に好まないが気にならない場合も含み、判断できない場合は「分からない」を選ぶ。

| 項目 | 詳細の文例 |
|---|---|
| 探索 | 自分のペースで隅々まで調べること／危険を警戒しながら先へ進むこと |
| 謎解き | 時間をかけてじっくり考えること／時間制限の中で判断すること |
| 物語 | 登場人物の感情に入り込むこと／先の展開や真相を追うこと／世界観や設定を味わうこと／冒険を一つの物語として体験すること／一本の道筋に沿って物語を最後まで追うこと／選択や行動によって、途中の物語が大きく分岐すること／主な道筋は共通で、終盤の行動などによって結末が変わること／別のルートを見るために、繰り返し遊ぶこと |
| 考察 | 断片的な手掛かりをつなぐこと／答えが一つに定まらない余韻 |
| 戦闘の上達 | 狙いやタイミングを練習すること／失敗しながら敵の対処法を覚えること |
| 爽快感 | 多くの敵を続けて倒すこと／最初は怖かった敵に反撃できるようになること／狙いどおりに攻撃や回避が決まること／手強い一体を倒したときの達成感／攻撃が当たったときの音や動きの気持ちよさ |
| 物資管理 | 限られた物資の使い道を判断すること／持ち物を準備して探索に出ること |
| 工夫 | 道具の使い方をいろいろ試すこと／限られた手段で慎重に作戦を立てること |

複数の好みは共存できる。例えば安全な探索も危険な探索も「好き」にできる。

### 問3：次のホラー表現は、好みに合いますか？

各項目を「好き／どちらでもない／避けたい／分からない」で任意回答。

- 突然の音や出現で驚かされる
- 敵に追われる
- 何か起きそうな不安が続く
- 残酷な描写や身体の変形
- 物語の意味を考えると怖くなる
- 日常の場所が少しずつ変わっていく

この回答から怖さへの耐性を推測しない。「怖くないが嫌い」「強く怖がるが好き」の両方を認める。

### 任意追加：好きな作品を教えてください

まず一作品から登録できる。好きな理由を問1・問2の項目、または短文で添える。登録は未プレイ作品への相性を保証しない。

## 3. 回答後のプロフィール例

架空のAさんは次のように回答した。

| 問い | 回答 |
|---|---|
| 楽しみ方 | 探索、考察、物資管理 |
| 探索の詳細 | 隅々まで調べる：好き。危険を警戒して進む：好き |
| 考察の詳細 | 手掛かりをつなぐ：好き。答えが定まらない余韻：未回答 |
| 物資管理の詳細 | 使い道を判断する：好き。準備して探索に出る：好き |
| ホラー表現 | 不安が続く：好き。追跡：どちらでもない。突然の驚き：避けたい。他は未回答 |

公開する項目は本人が選択する案。非公開の回答は他人向けの共通点表示や集計根拠として露出させない。

表示例:

> Aさんの好み（本人が選択）
>
> 好き：隅々まで探索／危険を警戒して進む／手掛かりをつなぐ／物資の使い道を考える
>
> ホラー表現：不安が続く演出が好き／突然の驚きは避けたい

人物タイプ名やレーダーチャートに固定しない。「追跡がどちらでもない」は「嫌い」と表示しない。

## 4. レビュー投稿の試案

### 全体として、自分の好みに合いましたか？

任意で「合った／どちらともいえない／合わなかった」。補足は「作品の出来の採点ではなく、自分の楽しみ方に合ったかを選んでください」。未選択で文章だけでも投稿可能とする案。

### 印象に残った点

自由文を中心にし、任意で次のまとまりを追加できる。初期表示は一件、必要な人だけ増やす。文章と同じ内容を何度も入力させない。

| 欄 | 入力例 |
|---|---|
| 話題 | 探索／戦闘／物語／謎解き／物資管理／追跡／演出／その他 |
| 今回の受け止め方 | 合った／合わなかった／両方ある／判断できない |
| 具体的には？ | 「燃料の残量を見て探索先を決めるのが楽しかった。ただ、荷物を預けるだけの往復は面倒だった」 |

構造化するのは話題と反応まで。原因や条件を必須の大量の選択肢にしない。本文のみの場合、初期版では自動分類を必須にしない。

怖さメーターは別項目で任意入力。強い怖さを高い満足度へ換算しない。プレイ状況・難易度・モードは体験を読むための背景として扱う。既存項目との統合は実装前に確認する。

## 5. Aさんのレビューが蓄積した例

| 作品 | 全体の感想 | 印象に残った点 |
|---|---|---|
| X | 合った | 燃料を見て探索先を決めるのが楽しい。荷物を預けるだけの往復は面倒 |
| Y | 合った | 敵を警戒して進むのは好き。発見した資料を読む間は落ち着けた |
| Z | 合わなかった | 追跡中に資料を読み切れず、同じ場所のやり直しが続いて話を追いにくかった |

この例で「追跡嫌い」と断定すると、Yの良かった体験を取りこぼす。検討すべき仮説は「危険のある探索は好きだが、読む・調べる時間は確保したい」。

将来自動分析を追加する場合の本人向け確認例:

> レビューY・Zでは、資料を落ち着いて読めるかについて書いています。
>
> 「読む・調べる時間は落ち着いて過ごしたい」は、普段の好みにも当てはまりますか？
>
> 当てはまる／この作品での感想／当てはまらない／保留

3件で十分という判定基準ではなく、処理の意味を説明する架空の例。元の記述へ戻れること、申告・候補・本人確認済みを区別することが条件。自動分析の閾値や精度は未決定。

「当てはまる」なら本人確認済みの好みとして追加できる。「この作品での感想」なら作品の反応だけに留める。無回答は承認ではない。過去のレビューはその時の体験として残し、現在の好みで書き換えない。

## 6. 読む側の表示例

架空のBさんは探索と考察が好きで、物資管理は未回答。

> Aさん — 作品Zは自分には合わなかった
>
> 好み：隅々まで探索／手掛かりをつなぐ／物資の使い道を考える
>
> あなたとの共通点：隅々まで調べること、手掛かりをつなぐことが好き
>
> 探索・追跡：合わなかった
>
> 「敵がいる緊張感は良かった。ただ、資料を読もうとすると追われ、話を追い切れなかった」
>
> 怖さ：本人の入力値を別表示

Bさんは共通点と理由から、自分も気になりそうか判断できる。物資管理の未回答を一致・不一致と扱わない。未登録の人には個別の共通点表示を出さず、公開された好みとレビューを読めるようにする。

ゲーム全体には平均点や相性点を出さず、個々の理由と怖さの分布を見せる案。理由別の集計・要約は初期版の必須としない。追加する際には件数、元投稿、モードや執筆時期の違いを扱う。

## 8. 試す範囲と、次に確かめること

最初に試すのは、任意アンケート、本人が選んだ好みの表示、理由付きレビュー、明示された共通点。文章の自動分析・好み更新の提案は後続候補で、初期版の成立条件にしない。

次はこの質問に実際に回答してみて、次を確かめる。

1. 自分の好みを無理なく表せるか。足りない項目、似すぎた項目はないか。
2. 「好きだが頻繁だと嫌」などの条件が、短文で補えるか。
3. 好きな作品と合わなかった作品の両方について、理由を書けるか。
4. 他人の好みと理由を読むことで、作品選びの判断材料が増えるか。
5. 質問やレビュー欄が多すぎないか。詳細質問を後回しにできるか。

まだ決めないもの：総合点の移行、DB構造、類似度の式、自動分析モデル、投稿数の閾値、ランキング。質問の意味と読む価値を確かめた後に検討する。

## 9. 好き・苦手から段階的に好みを集める方針

追記日: 2026-09-11

### 基本方針

設問は豊富に用意し、ユーザーがいつでも好きな項目に回答できるようにする。一度に答える設問数は少なくし、登録時のアンケート完了や自由文の入力を利用条件にしない。設定画面からの回答に加え、作品への反応を入口に少しずつ収集する。

タイトル詳細に「好き」「苦手」の入口を設ける案。ボタンを押した後、タイトルに付いた情報から関連する設問を選び、任意で詳しく回答してもらう。「好き・苦手」と既存の「合った・合わなかった」の関係、同時選択・変更・取り消しの仕様は今後決定する。

### 文字入力なしで回答できる流れ

1. タイトル詳細で「好き」または「苦手」を選ぶ。
2. 「どのあたりが好きでしたか？」など、その反応に関連する問いを出す。
3. 「舞台や雰囲気」「戦闘」「物語」「探索・謎解き」などを選ぶ。
4. 必要に応じて、選んだ分野に関連する具体的な項目を少数提示する。
5. 追加回答せず閉じることもできる。文章を書きたい人は補足やレビューを入力できる。

今回の試回答を踏まえた導線例:

> 作品を「好き」 → 「舞台や雰囲気」 → 「古い日本家屋」「幽霊」「映像表現」などを選択

この例は「古びた大きな日本家屋と幽霊が作る怖さの雰囲気」を、文章なしでもある程度残すことを狙う。ただし、複数要素の組み合わせによる好みを単独タグの集合で完全に表せるとは限らない。任意の補足も残せるようにする。

タイトルに付いた情報は、提示する設問の選定に使う。「作品が好き」という一回答から、その作品に含まれる全要素を自動的に「好き」と登録しない。未選択・未回答も「苦手」と扱わない。

### 情報の出どころを分ける

| 出どころ | 意味と用途 |
|---|---|
| 設定画面で本人が回答した好み | 普段の好みとして明示された情報。自動処理で変更しない |
| 作品ページの好き・苦手、追加の選択回答 | その作品・その要素への反応。普段の好みとは区別して蓄積する |
| レビュー本文のAI解析 | 作品での反応や好みの候補を推測する。推測として別管理する |
| 閲覧履歴 | 関心がありそうな作品や、次に提示する設問を選ぶ補助。好き嫌いと同一視しない |

本人が「ジャンプスケアは苦手」と設定していて、ジャンプスケアを含む作品を「好き」としても、設定は維持する。「その要素があっても、この作品は好き」という反応として扱う。

### AI解析の位置付け（追加提案・詳細未決定）

従来の5節では、推測を本人の好みに追加する前に確認する例を示した。今回の拡張案では、毎回の確認を必須にせず、自動で抽出した情報を「推測」として保存することも検討する。本人が選んだ設定への昇格・上書きとは別の処理とする。

- 推測には根拠のレビューを紐付け、本人が確認・訂正・削除できるようにする。
- 「この作品の戦闘は退屈」から、恒常的な「戦闘嫌い」を断定しない。まず作品単位の反応の整理に使う。
- 未確認の推測をマッチ度へ使うか、どの程度反映するかは未決定。初期版は明示された選択回答を基本とする。
- 初期版では自由入力を数値計算に直接使わず、人が読む補足として扱う。既存の項目に無理に当てはめない。

### 閲覧履歴とマッチ度（追加提案・詳細未決定）

閲覧には「好きだから見る」以外に「苦手要素を確認する」などの理由もある。履歴は好き嫌いの強い根拠にせず、質問選定や作品発見の補助から検討する。利用のオン・オフと履歴削除の導線も検討する。

マッチ度では、本人が明示した共通点と推測による情報を区別する。未回答を不一致にせず、「どちらでもない」の一致を「好き」の一致と同じ意味にしない。比較材料が少ない場合は、その少なさも示す。ユーザー同士の好みの近さと、ユーザーとゲームの適合は別に設計する。

### 実装順の提案

最初に「作品の好き・苦手 → 関連する点を選択 → 設定画面で見直す」という導線を検証する。既存の任意アンケートは、まとめて回答したい人向けに残す。その後、AI解析と閲覧履歴による補助を検討する。

本節は収集導線の方針追加であり、AI解析・履歴利用・計算式・公開範囲の確定や実装を意味しない。
